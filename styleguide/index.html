after—Image for the “after” side — same resolution rules. Required.

after_labelAfterTag text on the after side.
rulerafterWhich image’s aspect ratio sizes the box: before | after. The other image is cropped (object-fit: cover) to fill it.

Equations

Math is rendered by KaTeX 0.16.9, loaded from a CDN by layouts/partials/helpers/katex.html and switched on for every page by math = true under [params] in hugo.toml. Nothing needs enabling per page. Rendering happens in the browser on load, so the page source keeps the LaTeX verbatim.

Delimiters

SyntaxModeRenders as
$ ... $inlineflows inside the sentence
$$ ... $$displayits own centred block

These two are the only delimiters wired up. \( ... \) and \[ ... \] are not configured and would print literally. The KaTeX delimiter list and the Goldmark passthrough delimiters in hugo.toml have to agree, so adding a pair means editing both.

Multi-line, aligned

The \\ row separator works, but only because [markup.goldmark.extensions.passthrough] is enabled in hugo.toml. Without it, Goldmark parses the markdown inside the delimiters before KaTeX ever sees it and turns \\ into a <br>, which makes KaTeX throw a parse error instead of rendering.

$$
\begin{aligned}
P &= E + Q + \Delta S \\
Q &= Q_s + Q_b
\end{aligned}
$$
$$ \begin{aligned} P &= E + Q + \Delta S \\ Q &= Q_s + Q_b \end{aligned} $$

Gotchas

  • Two bare $ in one paragraph become math. KaTeX scans text nodes for delimiter pairs, so prose like “costs $5 and $10” would be read as one math span if those amounts were not in backticks, swallowing the words between them. A backslash does not help: Goldmark strips it and leaves a bare $ behind. Backticks do work — KaTeX skips code and pre elements, which is also why the source blocks on this page render as text rather than as equations.
  • Subscripts never needed escaping. $x_a + y_b$ is safe even without passthrough, because CommonMark does not apply _ emphasis inside a word.
  • * inside math does need passthrough. Unspaced $a*b*c$ would otherwise come out as $a<em>b</em>c$.

YouTube videos

Hugo’s own built-in shortcode — there is no project override. It is documented here because the parameter names are easy to forget. The video id is the v= value from the watch URL.

It gives a bare responsive iframe and nothing else. For a video that is a figure in a post — with a caption, credit and a width — use the ytvideo shortcode below instead.

Parameters

ParamDefaultDescription
id—Video id. Required. May be passed positionally as the first argument.
titleYouTube videotitle attribute on the iframe. Worth setting for accessibility.
start0Start offset in seconds.
end0Stop offset in seconds; 0 plays to the end.
autoplay01 autoplays. Browsers block this unless mute=1.
mute01 starts muted.
loop01 loops.
controls10 hides the player controls.
loadingeagerPass lazy for videos far down a long page.
class—Class for the wrapper div. See the gotcha below.

Default — positional id

{{< youtube dC8I9PD8V5A >}}

Named parameters

{{< youtube id="dC8I9PD8V5A" start="30" title="Beven on reading papers" loading="lazy" >}}

Gotcha: class drops the responsive wrapper

By default the shortcode wraps the iframe in a div carrying an inline padding-bottom: 56.25% style, which is what keeps the video 16:9 and full-width on mobile. Passing class replaces that inline style rather than adding to it, so the video collapses to zero height unless the class supplies its own aspect ratio. Leave class alone unless you are also writing the CSS for it.

ytvideo

YouTube embed wrapped in the same figure block as img — caption, credit, width, alignment. Use it whenever a video is a figure in the flow of a post; the built-in youtube shortcode above gives a bare iframe with none of that. layouts/shortcodes/ytvideo.html → layouts/partials/ytvideo.html.

Parameters

ParamDefaultDescription
id—Video id, or any URL it can be read from: watch?v=ID, youtu.be/ID, /embed/ID. Required.
titlethe caption, else YouTube videotitle on the iframe, which is what screen readers announce.
start—Start offset in seconds.
ratio16/9Aspect ratio as W/H. 4/3 for older footage, 9/16 for a vertical clip.
loadinglazylazy | eager. Defaults to lazy, unlike the built-in shortcode, since these sit in long posts.
caption""Caption text. Same behaviour as img.
credit"" → italic “Undefined”Same normalization as img: any existing (c)/© is stripped; output is always prefixed with a single ©.
width100%Player width. Bare numbers are percent (width=80 == "80%"); other CSS units pass through. Note img defaults to 70% — pass width=70 to match it. Desktop only: at ≤768px the figure always spans the full column.
alignleftSame as img: left | center | right.
width_captionmirrors widthSame as img. Pass 100 for the full text column regardless of player width.
align_captionleftSame as img: left (ragged-right) | center | right.

Code blocks

Fenced blocks are highlighted by Hugo’s built-in Chroma. hugo.toml sets markup.highlight.noClasses = false, so Chroma emits CSS classes instead of inline colours, and the palette lives in assets/code-highlight.css — catppuccin-latte for light, catppuccin-frappe for dark. That file’s header comment carries the hugo gen chromastyles commands to regenerate it.

Basic — the language tag sets the lexer

Put the language right after the opening fence. Omit it and there is no highlighting at all — just a plain <pre> with no chroma class.

```python
def hand(dem, drainage):
    return dem - drainage
```

def hand(dem, drainage):
    """Height above nearest drainage."""
    return dem - drainage

Nesting fences

Each source example above is wrapped in a four-backtick fence, because the block it shows uses three. A three-backtick wrapper would be closed by the inner fence instead of its own, silently shifting the rest of the page.

Showing shortcode source without running it

Every block on this page that displays shortcode source uses the comment form of the delimiters, {{< and >}}, which Hugo prints instead of executing. Without it the example would render the shortcode a second time.
